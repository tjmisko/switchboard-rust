# T01 katas

## 1. `fn first(ids: Vec<SessionId>) -> &str { ids[0].as_str() }`

It does not compile because the return type has an elided lifetime and there
is no reference parameter for it to be tied to ("missing lifetime specifier").
Even with a lifetime written in, the function would be returning a borrow of
`ids`, which the function owns and drops at the closing brace, so the `&str`
would dangle.

Two fixes:

1. Borrow the input instead of owning it: `fn first(ids: &[SessionId]) -> &str`.
   Elision now ties the output lifetime to `ids`, and the caller keeps the
   `Vec` alive for as long as it uses the result.
2. Return something owned: `fn first(ids: Vec<SessionId>) -> String` (with
   `ids[0].to_string()`), or move the id out of the vector,
   `fn first(mut ids: Vec<SessionId>) -> SessionId { ids.swap_remove(0) }`.
   Nothing borrows from the dropped `Vec`.

## 2. `names.iter().filter(|n| n.len() > 3)` with `names: &[&str]`

`names.iter()` yields `&&str` (a reference to each `&str` element). `filter`
hands its closure a reference to the item, so `n: &&&str`.

`n.len()` still works because method calls auto-deref: the compiler tries
`&&&str`, then `&&str`, then `&str`, then `str`, and finds `str::len(&self)`.
No `*` is needed, and the extra references cost nothing.

## 3. Why `Deref<Target = str>` does not let a `SessionId` pass as a `ToolUseId`

Deref coercion only unwraps a type to its `Target` at a coercion site: `&SessionId`
can become `&str` because `SessionId: Deref<Target = str>`. It never *builds*
a new type. There is no `Deref<Target = ToolUseId>` for `SessionId`, and
coercion never goes "up" from a `&str` into a newtype, so a function taking
`&ToolUseId` rejects `&SessionId`, and a `BTreeMap<ToolUseId, _>` cannot be
indexed with a `SessionId`.

What survives: nominal distinctness. The two ids are different types, and the
type checker keeps a session id out of every slot that names a tool call.

What is weakened: opacity. Once an id can pass for a `&str`, every `str` API is
open to it: `session.starts_with("toolu_")`, `session.as_str() == call.as_str()`,
or handing either one to any function that takes `&str`. Two different id
kinds can be compared or mixed *through* `&str`, and the compiler no longer
objects. The newtype stops hiding its representation; it only keeps its name.
