# T03 katas

## 1. Types along the `actor` chain

```rust
p.get("agent_id")                          // Option<&Value>
 .and_then(Value::as_str)                  // Option<&str>
 .and_then(SubagentId::from_hook)          // Option<SubagentId>
 .map_or(Actor::Agent, Actor::Subagent)    // Actor
```

`Actor::Subagent` is a tuple variant, and every tuple-variant (and
tuple-struct) constructor is a function item of type
`fn(SubagentId) -> Actor`. Function items implement `Fn`, `FnMut` and
`FnOnce`, so `Actor::Subagent` can go anywhere `|id| Actor::Subagent(id)`
would go, and `map_or` takes it as its `FnOnce(SubagentId) -> Actor`
argument. Same trick as `.map(ToolUseId::from)` and
`.map_err(ForwardError::Connect)` in T02.

## 2. `session_of(line: &str) -> Option<&str>`

Elision ties the output lifetime to `line`, the only reference parameter.
But the returned `&str` actually borrows from `v`, a local `Value` that is
dropped when the function returns, so the compiler reports "cannot return
value referencing local variable `v`". Parsing produced a fresh owned tree;
nothing in it points back into `line`.

Two signatures that fix it:

1. Let the caller own the parse and borrow from it:
   `fn session_of(v: &Value) -> Option<&str>`, body
   `v.get("session_id").and_then(Value::as_str)`. The result now borrows from
   an argument that outlives the call.
2. Return something owned:
   `fn session_of(line: &str) -> Option<String>` (or `Option<SessionId>`),
   body ending in `.map(str::to_owned)` (or `.map(SessionId::from)`). The
   copy is made before `v` dies.

## 3. `key: &str` versus `key: &'a str` in `str_at`

With `key: &str`, the key has its own anonymous lifetime, unrelated to `'a`.
The signature says the result borrows from `v` alone, which is true: the key
is only used to look up, never returned.

With `key: &'a str`, both parameters must share one lifetime, so `'a` is
forced to be no longer than the *shorter* of the two borrows. The result
`&'a str` would then be tied to the key too, and the caller would have to
keep the key alive for as long as it uses the result. The test
`should_return_a_str_that_borrows_from_the_value_not_from_the_key` builds
the key as a `String` inside an inner block and uses the result after that
block; with `key: &'a str` that fails with "`k` does not live long enough".
Nothing about the implementation changes; only what the signature promises
the caller.
