# T02 katas

## 1. `ok_or(FrameError::Missing("cmd"))` vs `ok_or_else(|| FrameError::Missing("cmd"))`

`ok_or` evaluates its argument eagerly, before it knows whether the `Option`
is `Some`. `ok_or_else` takes a closure and only runs it on `None`.

Here `ok_or` is right. `FrameError::Missing("cmd")` is a tag plus a
`&'static str`: building it is a couple of register moves and no allocation,
so doing it on the success path costs nothing and the closure would only add
noise. (Clippy's `or_fun_call` lint agrees: it fires on function *calls* in
the argument, not on enum construction.)

The other one matters when constructing the error does work: an allocation
(`UnknownName::new("phase", s)` copies `s` into a `Box<str>`), a `format!`,
a syscall, or anything with a side effect. With `ok_or` that work happens on
every call, including the ones that succeed; `ok_or_else` defers it to the
failure path. That is why `Phase::from_str` uses `ok_or_else`.

## 2. Types along the `optional_pid` chain

```rust
v.get("pid")                                       // Option<&Value>
 .map(|raw| {
     raw.as_u64()                                  // Option<u64>
        .and_then(|n| u32::try_from(n).ok())       // Option<u32>
        .ok_or(E)                                  // Result<u32, E>
 })                                                // Option<Result<u32, E>>
 .transpose()                                      // Result<Option<u32>, E>
```

`Option<Result<T, E>>` says "maybe there was a field, and if so maybe it was
bad". `transpose` turns it into `Result<Option<T>, E>`, "either it was bad,
or here is the field if there was one", which is the shape `?` wants: `None`
passes through as data, `Err` short-circuits.

## 3. `fn main() -> Result<(), BoxError>` and three different `?`s

`?` on an `Err(e)` returns `Err(From::from(e))` converted to the function's
error type. `BoxError` is `Box<dyn Error + Send + Sync + 'static>`, and std
provides one blanket impl:

```rust
impl<'a, E: Error + Send + Sync + 'a> From<E> for Box<dyn Error + Send + Sync + 'a>
```

So each concrete error only has to satisfy `Error + Send + Sync + 'static`.

Which impls make it work:

- `impl Error for FrameError` and `impl Error for StatError`, which I wrote in
  this task (`Error` requires `Debug + Display`; `Debug` is derived, `Display`
  is mine, and `source` is the only method I overrode).
- `Send + Sync` for both: automatic, because every field is `Send + Sync`
  (`serde_json::Error`, `ParseIntError`, `&'static str`, `Box<str>`).
- `impl Error for io::Error`: std's, not mine.
- The `From<E> for Box<dyn Error + ...>` blanket: std's, not mine. I wrote no
  `From` targeting `BoxError` at all, and could not have, because a blanket
  impl in std already covers it.
