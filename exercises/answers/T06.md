# T06 katas

## 1. Why `ancestors` needs `+ '_`

The returned iterator is a `Successors` whose step closure calls
`parent_of(proc_root, p)`, so the closure holds a copy of the `&Path` the
caller passed in. An `impl Trait` return type hides the concrete type, and by
default an `impl Trait` in return position only captures the lifetimes it
names, so without `+ '_` the compiler would complain that the hidden type
captures `proc_root`'s lifetime but the signature does not mention it. The
`'_` says "this iterator borrows whatever the one elided input lifetime
borrows", which is the `proc_root` path. It does not borrow `pid` or
`limit`: both are `Copy` values moved into the closure and the adapter.

(The closure also has to be `move`, or it would capture a reference to the
local variable `proc_root` itself, which dies when the function returns.)

## 2. `Vec<Cow<'_, str>>` versus `Vec<String>`

`should_repair_invalid_utf8_arguments_by_allocating` would still pass with
`Vec<String>`: it only checks the repaired text and that the bad argument is
`Owned`, and the assertion on the *valid* arguments being `Borrowed` in
`should_split_cmdline_on_nul_and_borrow_when_valid_utf8` is the one that
would fail (and would not compile, since `String` is not a `Cow`). The cost
is one heap allocation and a copy per argument on every sweep, for text that
was already valid UTF-8 and already lived in the `cmdline` buffer. `Cow`
lets the common case borrow and pays only for the rare repair.

## 3. The types `classify` receives

- `&stat.comm`: `stat.comm` is a `String`, so `&stat.comm` is `&String`,
  which deref-coerces to `&str` at the call site because the parameter is
  `&str`.
- `exe.as_deref()`: `exe` is `Option<PathBuf>`; `as_deref` turns it into
  `Option<&Path>` by borrowing the `PathBuf` and dereferencing it to `Path`.
  The function receives `Option<&Path>`.
- `&argv`: `argv` is `Vec<Cow<'_, str>>`, so `&argv` is `&Vec<Cow<str>>`,
  which coerces to `&[Cow<str>]`. The generic `S` is inferred as `Cow<str>`,
  which implements `AsRef<str>`, so `argv: &[S]` is `&[Cow<'_, str>]`.
