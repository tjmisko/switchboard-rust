Desired behaviour · reading JSON

  • Typed reads (string, non-blank string, unsigned integer, bool) return None when the key is absent or holds another type. A negative number is not a u64, and a whitespace-only string is blank.
  • A path walk descends one key at a time and stops at the first missing or non-object step. Array elements are not reachable by key. An empty path returns the value you started from.
  • "The elements of this key" yields each element of an array, and nothing at all for a string, an object or a missing key.
  • A returned &str lives as long as the JSON it came from, even when the key was a temporary.

Desired behaviour · the input hash

  • Two inputs that differ only in key order hash equal, at every depth. Arrays keep their order.
  • A hook's tool_input and the transcript's tool_use.input for the same call hash equal.
  • FNV-1a 64 over the canonical bytes: "" → cbf29ce484222325, "a" → af63dc4c8601ec8c.
  • On the wire the hash is exactly 16 lowercase hex digits. Parsing accepts either case and rejects any other length, any non-hex character, and a leading +.

Desired behaviour · scrubbing (the forwarder)

  • These fields never leave: tool_input, tool_response, prompt, last_assistant_message, message, custom_instructions, requested_schema.
  • When tool_input was present, tool_input_hash takes its place. Ids such as session_id, tool_use_id and agent_id survive.
  • The frame gains cmd: "hook", pid, and event, taken from argv, else from hook_event_name, else empty.
  • Stdin that isn't an object still yields a frame, with exactly cmd, event and pid.

Desired behaviour · hook → input

Every hook input is Confidence::Confirmed. The actor is the subagent named by agent_id when it's present, and the agent otherwise. A hook missing a field that its row marks required produces nothing.

Where replay starts. For a window of w bytes, the result is 0 when the file is no longer than w, including when it's empty. When the window begins exactly on a line boundary, it is that offset. When it begins mid-line, it is the start of the next line. When no line starts within the window, it is the end of the file.

Numbered lines. Numbers start at 1. Blank lines are not yielded, but they still take up a number. A line that isn't UTF-8 comes back as an error of kind InvalidData.

Desired behaviour · the history day file

  • One JSON object per line, written with a single call. Every line carries ts (UTC, milliseconds, Z), type and pid. session_id appears only when known.
  • session_start adds cwd. shown adds from, to and held_ms. session_end adds nothing.
  • Writing then reading any record gives back an equal record.
  • Reading never fails as a whole. The fixture reads like this:
