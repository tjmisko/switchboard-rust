The course is the rewrite itself. Every function you write ships in the daemon, and every task leaves the next one something real to stand on. The scaffold on main has all the types, doc comments and signatures. The bodies you write are todo!("T0N"), and pure plumbing is provided whole.

Five phases

Each phase ends with something you can observe, not just a passing suite. Phases 1–3 are strictly ordered. Phase 4's three tasks depend only on phase 3 and can be done in any order.

01 · vocabularyT01–T02 · 2¼ h. Identifiers pass for strings, and every boundary has an error type that says what went wrong. Ends with: a malformed socket line gets a precise, typed reply.
02 · reading the worldT03–T06 · 5 h. Hooks, transcripts, a tailing reader and /proc each become inputs. Ends with: any fixture payload or live process turns into the exact Events the model expects.
03 · the reducerT07–T09 · 4¼ h. Events, snapshots and time fold into a board, and the cost model decides what is shown. Ends with: a scripted story of an agent's life produces the right chip at every step.
04 · the runtimeT10–T12 · 3 h. One task owns the board, a socket feeds it, and watchers follow transcripts. Ends with: a dwell promoting itself with nothing sent.
05 · ship itT13 · ½ h plus stretch. Warnings off, release build, and your own agents on the socket. Ends with: the chip going red when you're asked to approve a call, and amber when you press Escape.

The loop, for every task

  1. Read the sheet in exercises/tasks/T0N-*.md, then the module comment of each file you'll touch. The spec lives in the doc comments.
  2. Take the checkpoints in order. Each one is a cargo test filter. Run it first and watch it fail on todo!. Implement until it passes, then tick it here.
  3. On test-first tasks (T02, T04, T07), the first checkpoint is writing the tests. A test counts as written when it compiles, exercises the behaviour its name promises, and fails inside the code under test. Failing in its own setup doesn't count: a socket that never bound, or a typo in a fixture path.
  4. Answer the katas in exercises/answers/T0N.md before looking anything up.
  5. Commit with the suggested message, then say "grade T0N". Grading runs the hidden suite for that task and clippy, then reviews your diff against the golden.
Done means all of these, for every task.
  • Every checkpoint passes, and so does the whole test file.
  • Everything before it still passes: cargo test shows no regressions in earlier tasks.
  • cargo clippy --all-targets adds no warnings in the files you touched.
  • No public signature changed. The hidden tests compile against them, so if you think one is wrong, raise it.
  • No unwrap or expect in library code outside tests, except where a comment proves it can't fail.

Changes to the model since your sketch

These are listed in full, with reasons, in exercises/README.md. The ones every task depends on:

  • Event carries process: Option<ProcKey> for routing, and confidence for settle.
  • Agent::session is optional, because a sweep finds processes before any hook names their session.
  • Turn keys are optional on both TurnStarted and TurnEnded.
  • Permission asks and parked prompts carry a GateKind.
  • SnapshotKind::Waits exists, and it's the only source for Waiting.
  • After the September 2026 capture: WaitKind gained Workflow and Other, Origin gained Unknown, ProcessRow carries the session file's name, and SUBAGENT_STALE bounds a subagent row nothing mentions.
  • The reducer lives in src/reduce/. Its effects are publish, append history, watch transcript, and forget.

Ticked checkpoints are stored in this browser's local storage under sbr-course. They are a record for you; grading only looks at your commit.
