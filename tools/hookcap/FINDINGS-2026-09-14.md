## O1: approval hooks do not identify the human owner

The user answered **“far fewer”** when asked whether the original 11 Codex
`PermissionRequest` events corresponded to roughly 11 visible approval prompts.
This is retrospective user evidence, recorded here rather than as a falsely
timestamped scenario mark.

The previous answer reversed its alternatives. Far fewer visible prompts supports
requests being handled automatically as well as by humans. It contradicts the
claim that every captured request represents a prompt handed to the user. It does
not prove that every automatic review emits a hook, identify each request's owner,
or establish a timing threshold for human attention.

The current total is 15 requests. All lack `tool_use_id`; all have Bash
`tool_input.command` and `description`. Four have the newly added `command_hash`.
In the same session and turn, their nearest matching `PreToolUse` records precede
the requests by **16, 21, 34, and 21 ms**. Two requests have earlier identical-command
candidates too, so selecting the nearest invocation is a temporal inference.

This corrects the earlier assertion that Codex requests arrive 8–38 seconds
before their calls. Those later calls were not established matches. The original
11 requests lack command hashes and remain unmatched by the corrected analyzer.
Do not implement “a later PreToolUse means approved” from the earlier report.

Only one of the four matched invocations has a corresponding `PostToolUse`,
identified by its call ID, 4.591 seconds after the request. That duration includes
tool execution. The other three have no captured matching completion; this alone
does not distinguish denial, interruption, or missing delivery. An unrelated call
finishing does not resolve a pending approval.

Final validation saw a 16th request at September 14 08:47:50, coinciding with
this recheck's attempted analyzer installation. Its nearest matching PreToolUse
was 13 ms earlier, and its matching PostToolUse was 5.950 seconds later. Thus the
final totals are five matched requests, all with PreToolUse first, two matching
completions, and 11 older unmatched requests. The four-request analysis above
describes the data present before this recheck's installation attempt.

The current official documentation lists `turn_id`, `tool_name`, and `tool_input`
for `PermissionRequest`, including an optional description, and describes hooks
that can decide a request before a prompt is surfaced. It does not supply a human
handoff signal in that payload. [OpenAI Hooks documentation](https://learn.chatgpt.com/docs/hooks#permissionrequest).

**Design implication:** retain unknown approval ownership unless there is separate
evidence of a visible human prompt. A 30-second grace remains a heuristic requiring
marked trials, not an established classifier. Scenario 13 now documents those marks.
