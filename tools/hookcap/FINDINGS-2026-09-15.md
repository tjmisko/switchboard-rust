# Capture findings: September 15, 2026

Third read of the recording, and the first that compares captured payloads against
the golden's code rather than against the design documents. Four defects are
reproduced by failing tests in `tests/t13_capture_findings.rs`; five further
mismatches are recorded without tests. Times are America/Los_Angeles.

Continues [September 14](FINDINGS-2026-09-14.md), which corrected the first
reading of Codex ordering. That correction stands: `PreToolUse` precedes
`PermissionRequest`.

## Recording health

- Three days recorded: about 51,000 hook records, 444 status-line records,
  87 subagent-panel records, and 369,000 process and session samples.
- One record of roughly 51,000 was torn: two hooks interleaved chunks of a
  single append (2026-09-13 line 5714). Appends are now serialised with
  `flock`; 60 concurrent hooks with 12 KB payloads produce 60 intact lines.
  A rewrite of that file earlier in the session may have contributed; the
  interleaving hazard is real either way, since a record can exceed the
  kernel's atomic append size.
- `error` was being stored as a shape marker, which hid the one field
  `StopFailure` exists to carry. Enum-shaped values (short, identifier-like)
  are now kept verbatim; prose is still reduced. The 56 `StopFailure` records
  captured before this change show `<str:10>`, a length consistent with
  `rate_limit` but not proof of it.
- All scripts and the corrected analyzer are deployed to
  `~/.local/share/switchboard-hookcap/`.
- Still no scenario marks. Everything below rests on passive observation.

## Confirmed defects

Each has a failing test in `tests/t13_capture_findings.rs`.

### 1. An answered question keeps the chip red

**Observed.** All three Claude `PermissionRequest` events were `AskUserQuestion`
in auto mode, each preceded by a `PreToolUse` for the same tool carrying a
`tool_use_id` and the same `tool_input`, 16 ms, 78 ms and 214 ms earlier. The
sampled session file showed `waitingFor: "input needed"` for all three, for
90.9 s, 14.7 s and 4 h 51 m.

**Golden.** `PreToolUse` for a question tool gates the call
(`src/ingest/claude/hook.rs:99`, `src/reduce/event.rs:396`). The following
call-less `PermissionRequest` finds no *running* call to join, because that call
is already blocked, so it parks a second prompt (`src/reduce/event.rs:420`).
`PostToolUse` then removes the call and returns before anything lifts the parked
prompt (`src/reduce/event.rs:351`). `Agent::wants_a_human` still sees the parked
prompt, so the phase stays `Attention` until the turn ends or the 30-minute
`UNJOINED_EXPIRY` elapses.

**Impact.** Every answered question leaves a red chip for the rest of the turn.

**Test.** `should_leave_attention_when_an_answered_question_was_announced_by_two_hooks`

### 2. A subagent's failed turn blocks the parent

**Observed.** 47 of 56 `StopFailure` payloads carry `agent_id`; the failing turn
belonged to a child. Claude attributes a large majority of tool activity to
children on this machine: 11,122 of 11,253 `PreToolUse` and 10,917 of 11,207
`PostToolUse` carry `agent_id`.

**Golden.** Every hook is built with the actor the payload names
(`src/ingest/claude/hook.rs:63`), but `TurnEnded` is applied to the agent
whatever the actor says (`src/reduce/event.rs:129`). A child's API failure
therefore ends the parent's turn and, through `Activity::Idle { after: Failed }`,
paints the parent `Blocked`.

**Test.** `should_keep_the_agent_working_when_a_subagents_turn_fails`

### 3. Status-line limits never parse

**Observed.** 408 of 423 status-line payloads carry
`rate_limits.{five_hour, seven_day}.{used_percentage, resets_at}`. Nine carry an
empty object, six carry `seven_day` alone. None carries `status`, `resetsAt` or
`utilization`.

**Golden.** `src/ingest/claude/statusline.rs:23` requires `rate_limits.status`
and returns nothing without it.

**Impact.** No `Limits` snapshot is ever produced from a real status line, so
`Phase::Blocked` from a usage limit cannot occur, and the `resets_at` that a
limit expiry would need never arrives. This also means the never-expiring limit
recorded as audit bug #1 is currently unreachable by this path.

**Test.** `should_read_rate_limits_from_the_status_line_shape_2_1_269_sends`

### 4. Delegating never expires

**Observed.** 168 Claude `SubagentStart` events and 124 `SubagentStop` events;
54 children have a start and no captured stop, 10 have a stop with no captured
start. Whether those children are alive is not established by their absence.

**Golden.** Rows are removed only by `SubagentEnded` (`src/reduce/event.rs:214`).
`tick` expires turns, waits, unjoined prompts and compaction, but never a
subagent row (`src/reduce/tick.rs:32`). One missed stop leaves the agent
`Delegating` for the life of the session.

**Test.** `should_stop_claiming_delegation_when_a_subagent_row_goes_stale`

## Further mismatches, not yet tested

5. **Session naming is lost.** 0 of 49 `SessionStart` payloads carry
   `session_title`, which is the only source `src/ingest/claude/hook.rs:75` reads
   for `Agent.title`. The name the operator recognises (`switchboard-rust-7f`)
   is in `~/.claude/sessions/<pid>.json`, which `src/proc.rs:129` opens and reads
   only for `sessionId`. The Go daemon reads the name from that file.

6. **Waits vocabulary is narrower than the payload.** Captured
   `background_tasks[].type`: `workflow` (4), `monitor` (3), `shell` (1).
   `waits()` maps anything without "monitor" to `WaitKind::BackgroundShell`
   (`src/ingest/claude/hook.rs:334`), so workflows are mislabelled. No
   `session_crons` element has ever been captured, so that shape stays inferred.

7. **`UserPromptSubmit` carries no `source`** in 83 of 83 events, so
   `prompt_origin` returns `Origin::Human` for every prompt
   (`src/ingest/claude/hook.rs:297`). A machine wake-up is then user-caused and
   escalates with no dwell. The transcript's `origin.kind` is the only
   discriminator available.

8. **The Codex join cannot work as specified.** Of 31 Codex
   `PermissionRequest` events, 20 match a `PreToolUse` by command hash, all with
   `PreToolUse` first by 13-60 ms; none of the 31 carries `tool_use_id`; all
   carry `tool_input.command` plus a `description` the call does not have. A
   whole-input hash therefore never matches. The documentation the September 14
   note cites lists no human-handoff field, so ownership stays unknown from
   hooks alone.

9. **`StopFailure`'s class is unrecorded so far**, per the scrub bug above. The
   adapter maps the string through `ErrorClass::from_wire`
   (`src/names.rs:193`); whether `rate_limit` is what arrives is still to be
   confirmed from records captured after this fix.

## Assumptions that held

- **Turn end.** `Stop` followed the transcript's last `end_turn` by a median of
  60 ms and at most 101 ms across 30 pairs. The "up to 32 s early" claim in the
  survey did not reproduce in this data.
- **Subagent dispatch.** All 22,049 subagent tool events named a child that a
  `SubagentStart` had already announced, so the reducer's "drop a dispatch for an
  unknown row" path was never exercised here.
- **Stale turns.** No turn contained an ungated silence longer than
  `TURN_STALE`. The five turns with silences of about 4 h 51 m were parked on an
  open question, which `tick` correctly refuses to end.
- **Claude `PermissionRequest` has no `tool_use_id`** in 3 of 3 events, as the
  model assumes.

## Addendum, evening: found while fixing

Counts re-read from the same three days after the fixes in
`docs/product/13-capture-fix-handoff.md` landed.

- **`UserPromptSubmit` keys differ by provider, not by version.** 101 of 101
  Claude prompts carry `prompt_id`; 183 of 183 Codex prompts carry `turn_id`
  and no `prompt_id`. (An earlier draft of this note read the Codex shape as
  a newer Claude one; the provider filter was missing.)
- **Status-line shapes, full count:** 537 payloads carry `five_hour` and
  `seven_day`, 6 carry `seven_day` alone, 9 carry `null`. All
  `used_percentage` values are integers; `1` means one percent.
- **Transcript `origin` is usually absent on typed prompts.** In the 40 most
  recent local transcripts, 35 human prompt lines carry no `origin` and 18
  carry `origin.kind: human`; every machine wake-up seen carried a kind. So
  the transcript adapter's "absent means human" stands, and only the hook
  side changed to `Unknown`.
- **`StopFailure.error`:** still 56 records, all `<str:10>`; nothing has
  arrived since the scrub fix, so the class remains unconfirmed.
